# Echo — Failure Test Matrix (P6)

This document specifies the resilience, recovery, and degradation behaviors of the Echo system under 17 distinct operational failure modes.

---

## Failure Matrix Overview

| # | Failure Mode | Trigger | Expected Behavior | User-Visible Behavior | Fallback | Recovery | Severity |
|---|---|---|---|---|---|---|---|
| **1** | **Hindsight Unavailable** | Network partition, DNS failure, or Hindsight Cloud 500/503 | Catch `HindsightError`, switch memory mode to `SEEDED DEMO FALLBACK` | Evidence panel displays badge `SEEDED FALLBACK` instead of `HINDSIGHT`. Case completes normally. | Local seeded experience memory (`seeded_experiences.json`) | Auto-retries Hindsight connection on subsequent requests; restores `HINDSIGHT` badge when healthy. | **Medium** |
| **2** | **Groq Unavailable** | Groq API rate limit (429) or service downtime (503) | LLM call fails; agent pipeline bypasses generative layer and uses deterministic rules | UI indicates deterministic reasoning mode without interruptions. No fake LLM output. | Deterministic domain logic (`ExportSimulator` & `DecisionAnalysis`) | Exponential backoff retry on Groq client; return to live generation when online. | **Medium** |
| **3** | **WebSocket Disconnect** | Network drop, client tab sleep, or proxy termination | Server catches `WebSocketDisconnect` and cleans up connection without crashing. Client triggers reconnect or HTTP fallback. | UI displays "Reconnecting..." indicator or switches transparently to HTTP polling/POST execution. | Transparent HTTP POST fallback to `/api/case` | Client establishes a fresh WebSocket connection with exponential backoff. | **Low** |
| **4** | **Frontend Cannot Reach Backend** | Backend service down, cold start, or wrong `VITE_BACKEND_URL` | Frontend network fetch fails with connection refused / timeout | UI displays prominent error banner: "Cannot reach Echo API. Verify backend is running on port 8000." | Offline demo mode using pre-rendered hero scenarios (if running in client-demo mode) | User restarts backend or refreshes once backend healthcheck reports green. | **High** |
| **5** | **Invalid Case Input** | Customer message contains malformed strings, emojis-only, or unrecognized problem | `ConversationAgent` returns `PARTIAL` extraction with `missing_fields`; pipeline returns `INCOMPLETE_CASE` (HTTP 422) | UI indicates missing parameters (e.g. export size, concurrency, or execution mode) with helpful guidance. | Prompt user to provide required parameters (`export_size_gb`, `concurrency`, `execution_mode`) | User re-enters or completes case details. | **Low** |
| **6** | **Empty Case Input** | User submits blank or whitespace-only customer message | Request validated at API boundary; rejected immediately with HTTP 422 `invalid_request` | Red validation message: "Customer message must not be blank." | Client-side form validation disables Submit button on empty text. | User types a non-empty message. | **Low** |
| **7** | **Malformed Hindsight Response** | Hindsight returns non-JSON, invalid schema, or missing fields | JSON decode error or validation error caught by `_remote_memories` / `_structured_experience` | Raw text retained in `remote_memories` for auditing; unparsed text skipped for deterministic reasoning. | Fall back to locally stored structured records. | Log warning and proceed with verified structured memories. | **Low** |
| **8** | **Hindsight Timeout** | Hindsight API response takes longer than `HINDSIGHT_TIMEOUT_SECONDS` (1.5s) | Client raises `TimeoutError` / `HindsightError`; switches to `SEEDED DEMO FALLBACK` | Decision delivered within SLA (<2s) with fallback badge. | Seeded local experiences used immediately. | Next query queries Hindsight again; timeout resets if remote responds. | **Medium** |
| **9** | **Groq Timeout** | Groq generation exceeds timeout threshold | Request times out; logs warning | Deterministic recommendation returned without delay. | Deterministic decision analysis output. | Subsequent calls attempt Groq with refreshed timeout. | **Medium** |
| **10** | **Simulator Failure** | Case parameters fall outside `ExportSimulator` supported actions or valid ranges | Simulator raises `ValueError("Unsupported action")`; pipeline halts with `DECISION_ANALYSIS_FAILED` | UI shows: "Could not evaluate action under current conditions. Escalation recommended." | Fall back to safe human escalation recommendation. | Investigation logs issue; team adds rule for novel domain pattern. | **High** |
| **11** | **Guardian Rejection** | Proposed recommendation is not supported by simulator evidence or transfers boundary memory | `Guardian.run()` sets `approved=False` with detailed `issues` list; pipeline returns `GUARDIAN_REJECTED` | Action blocked from automated execution; flagged with Guardian violation reasons. | Recommend human escalation / hold current mode. | Human engineer reviews the conflict. | **Low** |
| **12** | **Unknown Scenario** | Novel workload not matching any seeded experience conditions | Applicability check marks all experiences as `NON_TRANSFERABLE` or `BOUNDARY`; pipeline returns `NO_APPLICABLE_EXPERIENCE` | UI indicates: "No applicable historical experience found. Defaulting to standard baseline." | Baseline conservative recommendation (e.g. keep existing mode or escalate). | Retain new observed outcome once resolved to expand organizational memory. | **Low** |
| **13** | **Memory OFF** | System executed with zero memory or memory explicitly disabled | System evaluates initial action without historical context; returns baseline recommendation | UI displays "Generic Recommendation (Memory OFF): Increase timeout -> Expected Outcome: FAILURE". | Baseline generic heuristic. | Switch Memory ON to demonstrate contrast. | **Low** |
| **14** | **Memory ON** | System executed with historical memory enabled | Recalls prior failures/successes; identifies root bottleneck; selects optimal action | UI displays "Memory-Informed Recommendation (Memory ON): Async chunked export -> Expected Outcome: SUCCESS". | Primary system path. | System operates as designed. | **None** |
| **15** | **Seeded Fallback Mode** | Hindsight unavailable on boot or API key omitted | System initializes `ExperienceMemory` with local JSON dataset; sets `memory_mode="SEEDED DEMO FALLBACK"` | Demo runs 100% reliably with clear UI banner "SEEDED FALLBACK". | Local in-memory dictionary of 15 seeded experiences. | Add valid `HINDSIGHT_API_KEY` to `.env` to enable live cloud memory. | **Low** |
| **16** | **Backend Restart** | Render dyno reboots, container restarts, or crash recovery | Process restarts; loads configuration and seeded data; stateless REST/WebSocket re-binds port | Client temporarily disconnected (<5s); reconnects cleanly. | None required (memory is persisted in Hindsight Cloud). | In-flight requests can be re-submitted; Hindsight Cloud preserves state. | **Medium** |
| **17** | **Demo Reset** | Presenter resets demo to baseline state between judge runs | `demo_runner.py reset` clears local session cache and verifies baseline seeded memory bank | UI resets timeline to initial state; memory shows original baseline without contaminating previous runs. | Reload initial seeded dataset. | Deterministic clean state achieved for repeatable judge demos. | **Low** |
